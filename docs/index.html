the point

nine steps, or one.

you have a photo. you need a pdf. so you google “png to pdf”, pick one of the identical sites, and hand your file to a stranger's server.

the usual
  1. google “png to pdf”
  2. pick a site
  3. upload your file
  4. wait
  5. close a popup
  6. download it back
  7. find it in Downloads
  8. move it back
  9. delete the original
9 steps · 1 stranger's server
with suffix
  1. rename the file
invoice.png → invoice.pdf
1 step · 0 uploads

nothing is uploaded. nothing leaves your mac. there's no window to open, no file picker, no “drag your file here”. you already know how to rename a file.

things a filename can't say

“merge these three” has no filename to type it into. neither does “compress this, but how much?” so those live in the right-click menu.

merge into one pdf

pdfs, images, or a mix. they combine in the order you see them, named after whatever they have in common.

compress…

a smallest / balanced / best toggle and a quality slider. the estimated size is measured — it really compresses your first file at that setting — so the number moves when you do. if a file comes out bigger than it started, it gets thrown away instead of handed to you as an improvement.

create zip archive

separate on purpose. “compress” and “zip” are different verbs that english happens to spell the same.

install

getting it running

download the latest release, open the disk image, drag suffix to applications.

macos will block it the first time

suffix isn't signed with a paid apple developer certificate, so macos says it “cannot be verified”. that's gatekeeper reacting to a missing $99-a-year signature, not to anything the app does.

  1. open suffix and let macos block it
  2. go to system settings → privacy & security
  3. scroll to the line about suffix, click open anyway

you do this once.

then let it reach your files

macos protects desktop, documents and downloads. without access suffix keeps running but silently does nothing in exactly the folders you use most — so setup asks for full disk access, then offers a test it button that converts a real file to prove the whole chain works.

don't skip the test. a silent, healthy-looking failure is this app's characteristic way of going wrong, and the test catches it while you're still paying attention.

rather not trust a stranger's binary?

fair. build your own, takes about ten seconds:

git clone https://github.com/PewPewBiches/Suffix.git
cd Suffix && ./Scripts/build-app.sh && open build

○ mp3 needs a helper. macos ships an mp3 decoder but no encoder, so suffix uses ffmpeg or lame if one is installed — brew install ffmpeg. it looks for an encoder rather than bundling one. .m4a is the native equivalent and needs nothing.

read this before converting a document you plan to send. only iwork files convert exactly, because suffix asks pages or keynote to export them. everything else is re-laid-out by macos's own text engine: text and basic formatting survive, but tables, columns, headers and footers, and exact pagination do not. suffix says so on the notice — check the result.

faq

reasonable questions

do my files get uploaded anywhere?

no. suffix contains no network code at all — conversion uses only what ships with macos (imageio, pdfkit, avfoundation, vision). there's no account and nothing to sign in to.

what if it converts something i didn't mean to?

every conversion can be undone from the menu bar. the original is copied aside before anything is overwritten and kept for seven days, then deleted automatically so it doesn't quietly become a second copy of your photo library.

does the original file survive?

your choice, set during setup and changeable any time. replace leaves one file, as renaming implies. keep both leaves photo.pdf and photo.png side by side.

will it mangle files i rename for other reasons?

it only acts when the new extension is one it can actually produce and the contents don't already match. a .zip renamed to .png is untouched. archives, code and other apps' libraries are skipped entirely, and your photos library is never opened.

why does macos say it's from an unidentified developer?

because it is. signing costs $99 a year and this is free. the code is all on github if you'd rather build it yourself — it's one command.

is it actually free, or free-for-now?

free, mit licensed, no accounts, no pro tier. if it ever stops being maintained you still have the source.
